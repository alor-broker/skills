# Указания для работы с навыками

- Корневой `config.json` отдельного навыка содержит схему полей `veles`, а пользовательские значения живут в основной конфигурации Велеса под `skills.entries.<имя>.config`. Не записывайте пользовательские адреса и секреты в схему.
- Секреты объявляются в метаданных `SKILL.md` и передаются Велесом через окружение из зашифрованного хранилища. Не добавляйте значения секретов в репозиторий.
- Навык `blog` читает логин только из `skills.entries.blog.config.username`, пароль приложения — из секрета `BLOG_APP_PASSWORD`. Старый секрет `BLOG_USERNAME` игнорируется: не возвращайте неявное чтение логина из окружения. По умолчанию `/wp/v2` получает HTTP Basic, обложку `featured_media` и HTML тела. Явный `apiBaseUrl`, оканчивающийся на `/author-app/v1`, выбирает обмен пароля через `/auth/session` и токен в памяти, а изображения — через `image_media_ids`. `BLOG_TOKEN` не используется. Адрес блога и адрес публикации могут различаться. Его программа требует явный `--config`, чтобы не выбрать конфигурацию другого экземпляра Велеса, и никогда автоматически не повторяет операции записи с неопределённым результатом.
- Ошибки навыка `blog` должны сохранять номер HTTP и ограниченные поля кода и сообщения WordPress с удалёнными секретами. Не объединяйте 401/403 в безликий отказ и не объясняйте отказ как потерю соединения. `check-auth` в стандартном режиме читает личность и разрешения; в режиме author-app создаёт сеанс авторизации и читает `/config`, не создавая содержимого. Ограничения реализации не запрещают исследовать другие методы по явному поручению пользователя.
- Правила пользователя для `blog`: перед публикацией показать полный окончательный материал и получить подтверждение после просмотра; MOV преобразовывать в отдельный MP4 через ffmpeg (установка из доверенного источника разрешена при необходимости), сохраняя оригинал; не удалять записи, вложения или файлы даже по просьбе пользователя. Это правила инструкций агенту, а не встроенная проверка подтверждения в программе.
- Программа `blog/scripts/upload_video.py` отвечает только за загрузку готового MP4 в существующий черновик и проверку задания author-app. В ней нет преобразования, создания/публикации записей или удаления. MOV преобразует агент через FFmpeg CLI по инструкции; `blog.py create` поддерживает пустой черновик, `publish` меняет только статус после подтверждения. Сохраняйте выведенные job_id и ключ идемпотентности; продолжение через --job-id только проверяет обработку, не повторяет передачу файла.
- Для MOV→MP4 сначала проверять кодеки: совместимые потоки перепаковывать через FFmpeg `-c copy`, а не кодировать повторно. Наблюдать прогресс отдельного процесса каждые 30–60 секунд; общий таймер разговора не является временем FFmpeg. Преобразование остаётся только инструкцией для оболочки, не кодом загрузчика.
- В общении навыка `blog` статус публикации и доступные ссылки обязательны: до подтверждения явно писать «Черновик — НЕ ОПУБЛИКОВАН» и автоматически давать прямую ссылку на видео; после публикации — окончательный публичный адрес и видео. Черновой permalink не является публичным просмотром: не отправлять его как обычную ссылку на запись, ссылки на редактор помечать как требующие входа. Не заставлять пользователя отдельно просить уже известные ссылки.

- Оформление навыков хранится в `agents/openai.yaml` (`interface`), оригинальный значок — в `assets/icon.svg`; пути считаются от корня навыка. Сохраняйте `name` и инструкции `SKILL.md`, а также существующие разделы `policy`/`dependencies` других клиентов. `skills.json` версии 1 создаёт Велес, не добавляйте его в исходный репозиторий. Требования — `docs/marketplace_requirements_ru.md`; при добавлении или переименовании навыков обновляйте `docs/skills_catalog_ru.md` и число навыков в README.
