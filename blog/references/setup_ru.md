# Публикации в блоге

Навык `blog` поддерживает два способа работы с WordPress. Оба используют логин WordPress из обычной настройки `skills.entries.blog.config.username` и пароль приложения из зашифрованного секрета Велеса. Способ выбирается адресом программного интерфейса, без автоматических попыток подобрать другой сервер.

## Настройка

Установите каталог `blog` в рабочую область Велеса. Пользовательские адреса находятся в основном `config.json` Велеса под `skills.entries.blog.config`. Файл `blog/config.json` внутри навыка содержит только схему полей: не записывайте туда значения или пароли.

Для обычного WordPress задайте `blogUrl` и `username`; по умолчанию используется `<blogUrl>/wp-json/wp/v2`. В этом режиме логин и пароль приложения передаются через стандартную HTTP-авторизацию по HTTPS.

Для сайта с Writer Studio, принимающего пароль приложения через создание сеанса, настройте явно:

```json
{
  "skills": {
    "entries": {
      "blog": {
        "config": {
          "username": "gavrilenko",
          "blogUrl": "https://gavrilenko.ag",
          "apiBaseUrl": "https://ag.yourwpcare.com/wp-json/author-app/v1"
        }
      }
    }
  }
}
```

Это фрагмент для объединения с существующим файлом. В режиме `author-app/v1` программа передаёт логин и пароль приложения на `/auth/session`, а последующий запрос подписывает полученным токеном. Такой способ подтверждён публичным кодом Writer Studio; успешность конкретных сохранённых учётных данных ещё нужно проверить. Адрес `lk.yourwpcare.com` обслуживает интерфейс Writer Studio и не заменяет адрес программного интерфейса WordPress.

Поддерживаются только явно настроенные HTTPS-адреса без паролей в адресе, параметров запроса и фрагментов. `apiBaseUrl` должен оканчиваться на `/wp/v2` либо `/author-app/v1`.

## Секреты

В WordPress откройте **Пользователи → Профиль → Пароли приложений**, создайте пароль приложения и сохраните в разделе **Секреты** Велеса:

| Поле | Значение |
| --- | --- |
| `skills.blog.env.BLOG_APP_PASSWORD` | Пароль приложения; не основной пароль входа |

Логин задаётся отдельно в обычном поле `username`, например `gavrilenko`; это не название приложения и не пароль. При обновлении заполните `skills.entries.blog.config.username`: старый секрет `BLOG_USERNAME` больше не читается и не влияет на выбранный логин. Автоматического переноса из старого секрета нет. Существующий `BLOG_APP_PASSWORD` можно оставить. Пробелы между группами символов пароля удаляются автоматически. `BLOG_TOKEN` не используется. Пароль не должен попадать в обычные настройки, команды, файлы публикаций или переписку. Предварительный просмотр показывает настроенный логин, чтобы его можно было проверить до отправки.

Полученные токены находятся только в памяти одной команды и не записываются на диск. Следующая команда создаёт новый сеанс. Продление токенов и завершение сеансов на сервере не реализованы; серверные сеансы могут сохраняться до истечения срока действия.

## Проверка доступа

```text
python <каталог-навыка>/scripts/blog.py --config <конфигурация-Велеса> check-auth
```

В стандартном режиме команда читает сведения о пользователе, его роли и разрешения: `edit_posts`, `publish_posts`, `upload_files`. В режиме Writer Studio она создаёт сеанс авторизации и читает `/config`; этот ответ не следует выдавать за сведения о ролях WordPress. Ни один вариант не создаёт публикаций или изображений.

При ошибке выводятся `http_status`, `wp_code`, `wp_message` и, при наличии, этап `phase`. Поля ограничены по длине, пароли и токены скрываются; необработанные страницы ошибок и прочие данные не выводятся. Ответ ошибки ограничен 64 КиБ, успешный ответ — двумя МиБ.

`rest_not_logged_in` означает, что запрос не распознан как авторизованный. Он не доказывает неверность пароля или отсутствие прав публикации. Возможны удаление заголовка авторизации промежуточным сервером, ограничения расширений и другой предусмотренный сайтом способ входа. Поддерживаемые программой операции не запрещают исследовать другой способ по явному поручению пользователя; сначала проверьте его контракт, а не перебирайте адреса с секретами.

## Подготовка и публикация

Подготовьте локальный файл с полями `title`, `content` и явным `status`. Используйте HTML; Markdown автоматически не преобразуется.

Стандартный режим поддерживает `draft` и `publish`, обложку `featured_media` и дополнительные изображения внутри HTML тела. В режиме Writer Studio поддерживаются `draft`, `publish` и список изображений `image_media_ids`. Для подготовки видео можно создать черновик с пустым `content`:

```json
{
  "title": "Заголовок статьи",
  "content": "<p>Текст статьи.</p>",
  "status": "publish",
  "image_media_ids": []
}
```

Не используйте `image_media_ids` для стандартного `/wp/v2`. Номера изображений берите из реальных ответов загрузки. Шаблон блога Гавриленко отдельно выводит обложку и прикреплённые изображения; их повторная вставка в тело может создать дублирование.

Предварительный просмотр не требует секретов и подключения к сети:

```text
python <каталог-навыка>/scripts/blog.py --config <конфигурация-Велеса> create --payload <файл-публикации>
```

Загрузку изображений выполняйте в пределах поручения пользователя. Перед отправкой записи на публикацию обязательно покажите её целиком и получите отдельное подтверждение, как описано ниже:

```text
python <каталог-навыка>/scripts/blog.py --config <конфигурация-Велеса> upload --file <фотография> --execute
python <каталог-навыка>/scripts/blog.py --config <конфигурация-Велеса> create --payload <файл-публикации> --execute --confirmed
python <каталог-навыка>/scripts/blog.py --config <конфигурация-Велеса> get --post-id <номер-записи>
```

Команды создания и загрузки без `--execute` выполняют только локальную проверку. Поддерживаются PNG, JPEG, GIF и WebP до 20 МиБ на файл; сервер может устанавливать меньший предел. Параметр `--alt-text` доступен для стандартного WordPress; в режиме Writer Studio используйте редактор изображений сайта для описаний.

Сравните прочитанную запись с исходным материалом: WordPress может очищать HTML. Полученный номер и ссылка не заменяют проверку общедоступности публикации. Используйте среду Python Велеса с библиотеками `httpx` и `Pillow` и явно передавайте действующий файл конфигурации.

## Восстановление и ограничения

Если создание сеанса завершилось ошибкой, программа сообщает, что запрос содержимого не отправлялся. Явный отказ 401/403 не равен потере соединения и не доказывает создание записи. После диагностики пользователь может поручить новую попытку.

Автоматических повторов нет. После обрыва соединения или ошибки сервера при отправке содержимого операция могла завершиться. Сначала проверьте сайт, сохраните полученные номера и используйте уже загруженные изображения при продолжении. Не создавайте вторую запись из-за потерянного ответа.

Публикация существующего черновика реализована командой `publish`, а загрузка готового MP4 и проверка обработки — отдельной программой `upload_video.py`. Произвольное редактирование содержимого существующих записей, расписание и комментарии пока не реализованы. Их можно добавить по поручению пользователя с сохранением правил подтверждения и обработки видео. Удаление отдельно запрещено пользовательским правилом навыка. При этой доработке действующие секреты не использовались, публикации и автоматические проверки не выполнялись.

## Обязательные правила

### Подтверждение публикации

Перед любым действием, которое делает запись общедоступной, Велес отправляет пользователю полный окончательный вариант: заголовок, весь текст без сокращений, ссылки, подписи, обложку и все изображения или видео в нужном порядке. Сами материалы должны быть доступны для просмотра. Также указывается целевой блог. Краткого пересказа или результата проверки файла недостаточно.

После этого Велес спрашивает: «Вы уверены, что хотите опубликовать именно эту запись в этом блоге?» — и ждёт положительного ответа. Первоначальная просьба «опубликуй» или «создай тестовую запись» не заменяет подтверждение после просмотра. При изменении текста, заголовка, материалов или блога нужно показать новую версию и подтвердить её снова. Неизменённую уже подтверждённую версию повторно согласовывать не требуется. Без подтверждения запись остаётся неопубликованной.

### Видео MOV

Здесь ffmpeg — установленная на компьютере программа командной строки FFmpeg. Велес запускает её через оболочку; это не отдельный инструмент языковой модели.

Перед загрузкой файла `.mov` Велес преобразует его в отдельный `.mp4` через ffmpeg. Простого переименования недостаточно. Если ffmpeg отсутствует, пользователь разрешает установить его из официального источника или через обычный доверенный менеджер пакетов, в пределах разрешений среды. Установка нужна только при фактической обработке видео.

Исходный файл сохраняется. Для результата выбирается новое имя, а перезапись запрещается параметром `-n`. Предпочтительны видео H.264, звук AAC при его наличии и подготовка MP4 к быстрому началу воспроизведения. Нужно сохранить ориентацию, пропорции и содержание, проверить готовый файл и предоставить его для просмотра перед подтверждением публикации. При невозможности установки или преобразования загрузка останавливается. Преобразование выполняет агент через оболочку. Программа `upload_video.py` не запускает ffmpeg и принимает только готовый MP4.

### Запрет удаления

При использовании навыка Велес ничего не удаляет, даже по просьбе пользователя или ради очистки: ни записи, ни черновики, ни вложения, ни задания обработки видео, ни исходные, преобразованные или временные файлы. Перемещение в корзину, отсоединение вложения ради удаления и перезапись исходного материала также запрещены. Правило действует для всех инструментов, включая команды, браузер и программный интерфейс.

При ошибке материалы сохраняются, а пользователь получает описание оставшегося состояния. Если поступает просьба удалить что-либо, Велес объясняет, что удаление в этом навыке отключено, и оставляет данные без изменений. Эти ограничения заданы в инструкциях агенту; программа сама не проверяет факт подтверждения в переписке.

## Загрузка готового MP4

Работает с явно настроенным интерфейсом `author-app/v1`. Подготовьте видео по правилам выше, затем создайте один черновик с окончательным заголовком и текстом. Для записи только с видео текст может быть пустым:

```json
{"title":"Название видео","content":"","status":"draft","image_media_ids":[]}
```

```text
python <каталог-навыка>/scripts/blog.py --config <конфигурация-Велеса> create --payload <файл-черновика> --execute
```

Сохраните возвращённый номер записи. Загрузите в неё MP4:

```text
python <каталог-навыка>/scripts/upload_video.py --config <конфигурация-Велеса> --post-id <номер-черновика> --file <видео.mp4> --cors-origin https://lk.yourwpcare.com --execute
```

Для другого сайта укажите его адрес Writer Studio в `--cors-origin`. Без `--execute` программа только проверяет локальный файл и показывает параметры. Максимальный размер файла в этой программе — 2 ГиБ; сервер может устанавливать меньший предел. Наличие расширения и заголовка MP4 проверяется программой, а воспроизводимость и кодеки проверяет агент до загрузки.

Программа проверяет, что запись является черновиком, создаёт задание, передаёт файл потоком и проверяет обработку. Она не преобразует видео, не создаёт записи, не публикует и не удаляет их. Подписанный адрес загрузки остаётся в памяти; пароль и токен WordPress не отправляются в Mux.

Перед созданием задания выводится ключ идемпотентности, перед передачей файла — `job_id`. Сохраните их в контексте задачи. После передачи обработка проверяется с увеличивающимся интервалом. Бюджет ожидания задаётся `--wait-seconds` от 0 до 60, по умолчанию 60 секунд; отдельные сетевые запросы имеют собственные ограничения времени.

Если обработка ещё идёт, продолжайте проверку того же задания:

```text
python <каталог-навыка>/scripts/upload_video.py --config <конфигурация-Велеса> --post-id <номер-черновика> --job-id <идентификатор-задания> --wait-seconds 60
```

Этот вызов не создаёт нового задания и не передаёт файл повторно. При завершении программа читает запись и проверяет, что в ней появилось видео именно этого задания. `attachment_unverified` означает, что привязка пока не подтверждена: публикацию нужно отложить. `failed` сообщает об ошибке обработки. Исходники и черновик сохраняются при любом исходе.

При обрыве передачи не запускайте новую загрузку автоматически. Продолжение через `--job-id` проверяет состояние, но не возобновляет передачу отдельных частей файла. Если идентификатор задания не получен, сверяйте результат создания по выведенному ключу идемпотентности в кабинете или журналах сайта. Наличие ключа не является основанием для слепого повтора запроса.

После успешной обработки прочитайте весь черновик:

```text
python <каталог-навыка>/scripts/blog.py --config <конфигурация-Велеса> publish --post-id <номер-черновика>
```

Этот вызов только показывает запись. Отправьте пользователю полный текст и видео, запросите подтверждение и дождитесь положительного ответа. После этого:

```text
python <каталог-навыка>/scripts/blog.py --config <конфигурация-Велеса> publish --post-id <номер-черновика> --execute --confirmed
```

Команда меняет только статус и затем читает результат. Уже опубликованная запись не отправляется повторно. Флаг `--confirmed` означает, что вызывающий агент получил подтверждение; сама программа не читает переписку. Агент должен убедиться, что содержимое не изменилось после согласования. Другие пользователи WordPress могут редактировать запись одновременно; серверной блокировки содержимого в этом протоколе нет.
