# Публикации в блоге

Навык `blog` работает через стандартный программный интерфейс WordPress и пароли приложений. Он готовит записи, загружает изображения, создаёт черновики или публикации и читает результат для проверки. Дополнительное расширение `author-app` не требуется.

## Настройка адреса

Установите каталог `blog` через каталог навыков Велеса или поместите его в `skills` своей рабочей области. В настройках навыка задайте публичный адрес `blogUrl`. Пользовательское значение хранится в основном `config.json` Велеса:

```json
{
  "skills": {
    "entries": {
      "blog": {
        "config": {
          "blogUrl": "https://gavrilenko.ag"
        }
      }
    }
  }
}
```

Это фрагмент для объединения с существующей конфигурацией, а не замена всего файла. По умолчанию запросы направляются на `<blogUrl>/wp-json/wp/v2`. Если WordPress доступен по другому служебному адресу, укажите полный адрес в необязательном поле `apiBaseUrl` того же раздела. Он должен оканчиваться на `/wp/v2`. Поддерживается HTTPS без паролей в адресе, параметров запроса и фрагментов.

При переходе с предыдущей версии удалите старое значение `apiBaseUrl`, оканчивающееся на `/author-app/v1`, либо замените его проверенным адресом стандартного интерфейса WordPress. Программа отклонит старый маршрут до отправки учётных данных. Она не меняет пользовательскую конфигурацию автоматически.

Файл `blog/config.json` внутри навыка описывает только поля настройки. Не записывайте туда пользовательские адреса или пароли.

## Учётные данные

В WordPress откройте **Пользователи → Профиль → Пароли приложений**, создайте пароль с названием «Велес» и сохраните показанное значение в разделе **Секреты** Велеса:

| Поле секрета | Значение |
| --- | --- |
| `skills.blog.env.BLOG_USERNAME` | Логин пользователя WordPress, например `gavrilenko`; не название приложения |
| `skills.blog.env.BLOG_APP_PASSWORD` | Созданный пароль приложения; не основной пароль входа |

Велес хранит оба значения зашифрованными и передаёт программе на время выполнения. Пробелы между группами символов пароля удаляются автоматически. Значение `BLOG_TOKEN` больше не используется. Не переносите его в новое поле и не помещайте пароли в обычные настройки, команды или файлы публикаций.

Проверить вход без создания записи можно так:

```text
python <каталог-навыка>/scripts/blog.py --config <конфигурация-Велеса> check-auth
```

Команда читает сведения о текущем пользователе. Успешный ответ подтверждает вход, но сам по себе не гарантирует право публиковать записи или загружать файлы. При отказе проверьте логин, пароль приложения, разрешения пользователя и доступность паролей приложений на сайте. [Официальная инструкция WordPress](https://developer.wordpress.org/advanced-administration/security/application-passwords/).

## Подготовка и отправка

Например: «Подготовь статью для моего блога и покажи перед публикацией» или «Опубликуй согласованный текст с этими фотографиями».

Велес готовит точный заголовок, текст, изображения и выбранный статус. Отправка требует поручения пользователя; уже полученное разрешение на конкретный материал повторно не запрашивается. Загрузка файлов и создание удалённого черновика также изменяют сайт.

Пример локального файла публикации:

```json
{
  "title": "Заголовок статьи",
  "content": "<p>Текст статьи.</p>",
  "status": "publish"
}
```

Для удалённого черновика выберите `status: "draft"`. Без `--execute` оба варианта остаются только локальным просмотром и не требуют секретов или подключения к сайту:

```text
python <каталог-навыка>/scripts/blog.py --config <конфигурация-Велеса> create --payload <файл-публикации>
```

Для загрузки изображения:

```text
python <каталог-навыка>/scripts/blog.py --config <конфигурация-Велеса> upload --file <фотография> --alt-text "Описание фотографии" --execute
```

Поддерживаются PNG, JPEG, GIF и WebP до 20 МиБ на файл. Сайт может устанавливать меньший предел. Ответ содержит номер `id` и адрес `source_url`. Для обложки добавьте в файл публикации `featured_media` с полученным номером. Дополнительные изображения вставляйте в HTML тела статьи, используя полученные адреса и экранируя значения атрибутов. Автоматического преобразования Markdown нет.

Старое поле `image_media_ids` не поддерживается стандартным WordPress: программа отклоняет его, чтобы фотографии не потерялись незаметно. Переданный шаблон блога Гавриленко уже выводит обложку после текста; повторная вставка той же обложки в тело может продублировать изображение. Пользовательские поля темы не изменяются.

После проверки окончательного текста отправьте его один раз и прочитайте результат:

```text
python <каталог-навыка>/scripts/blog.py --config <конфигурация-Велеса> create --payload <файл-публикации> --execute
python <каталог-навыка>/scripts/blog.py --config <конфигурация-Велеса> get --post-id <номер-записи>
```

Чтение использует режим редактирования, позволяющий сравнить исходные заголовок и текст (`title.raw`, `content.raw`), статус и обложку. WordPress может очищать HTML. Ссылка на черновик не означает, что он доступен всем читателям.

## Ограничения

Программа требует явный путь к действующей конфигурации Велеса, не изменяет её и не печатает содержимое. Используются библиотеки `httpx` и `Pillow`, входящие в среду Велеса. Секреты не пересылаются при перенаправлении; ответ ограничен двумя МиБ, тела ответов с ошибками не выводятся.

Автоматических повторов записи нет: после обрыва соединения изображение или публикация уже могли появиться. Сначала проверьте WordPress, сохраните полученные номера и используйте уже загруженные файлы при продолжении. Не создавайте вторую запись из-за потерянного ответа.

Редактирование существующей записи, включая публикацию ранее созданного черновика, удаление, расписание, видео и комментарии пока не реализованы. Для этих действий используйте WordPress. При разработке навыка действующие учётные данные не использовались, публикации и автоматические проверки не выполнялись.
