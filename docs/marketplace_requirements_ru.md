# Требования к маркетплейсам навыков Велеса

Этот документ описывает формат, поддерживаемый текущей реализацией Велеса
на 9 ноября 2026 года. Он разделяет **содержимое исходного репозитория**,
**оформление карточки** и **служебный каталог, создаваемый Велесом**.

## Устройство репозитория

Маркетплейс — репозиторий Git с одной или несколькими папками навыков.
Велес рекурсивно находит `SKILL.md`; специальный корневой манифест или
подготовленный вручную `skills.json` для подключения не нужен.

```text
repository/
├── README.md
├── docs/
│   └── marketplace_requirements_ru.md
└── my-skill/
    ├── SKILL.md
    ├── config.json              # при наличии обычных настроек
    ├── agents/
    │   └── openai.yaml          # оформление карточки
    ├── assets/
    │   └── icon.svg
    ├── scripts/                # при необходимости
    └── references/             # при необходимости
```

Идентификаторы навыков уникальны во всём репозитории, включая вложенные папки.
Символические ссылки и соединения каталогов не входят в переносимый пакет:
ресурсы должны быть обычными файлами внутри папки навыка. Служебная `.git`
исключается. Не храните в пакете временные файлы, окружения, кэши Python,
пользовательские результаты или учётные данные.

## Описание и инструкции навыка

`SKILL.md` — текст UTF-8 с заголовком YAML в самом начале файла:

```yaml
---
name: my-skill
description: "Готовит краткий обзор публикаций по указанной теме. Использовать для обзоров литературы."
metadata:
  veles:
    emoji: "📚"
---
```

После заголовка расположены инструкции в Markdown. Пример выше нужно дополнить
реальными инструкциями; он не является готовым навыком.

| Поле | Требование Велеса |
| --- | --- |
| `name` | Обязательно; совпадает с именем папки; не более 64 символов. Строчные латинские буквы, цифры и одиночные дефисы между частями; без начального и конечного дефиса. |
| `description` | Обязательная непустая строка до 1024 символов: назначение и условия применения для модели. |
| `license` | При наличии — непустая строка. Сохраняйте лицензии и сведения об исходных авторах. |
| `compatibility` | При наличии — непустая строка до 500 символов. |
| `allowed-tools` | При наличии — строка; наличие поля само по себе не подтверждает выдачу разрешений. |
| `metadata` | Объект с ключами-строками и значениями-строками или объектами; прежняя запись этого объекта строкой JSON также принимается. |

Видимое название карточки не заменяет `name`: идентификатор участвует в установке,
настройках и обращении `$my-skill`. Не переименовывайте папку ради более красивого заголовка.

## Оформление карточки

В `agents/openai.yaml` используется совместимый с OpenAI раздел `interface`:

```yaml
interface:
  display_name: "Обзор публикаций"
  short_description: "Источники и выводы по выбранной теме"
  icon_small: "./assets/icon.svg"
  icon_large: "./assets/icon.svg"
  brand_color: "#0891B2"
  default_prompt: "Используй $my-skill для обзора публикаций по моей теме."
```

| Поле | Ограничение Велеса |
| --- | --- |
| `display_name` | Непустая строка, до 120 символов. |
| `short_description` | Непустая строка, до 500 символов. Для удобства чтения рекомендуются 25–64 символа. |
| `icon_small`, `icon_large` | Относительные пути от корня навыка, до 500 символов. |
| `brand_color` | Шесть шестнадцатеричных цифр после `#`, например `#0891B2`. |
| `default_prompt` | Непустая строка, до 2000 символов; полезный пример с `$имя-навыка`. |

Все значения в примерах заключены в кавычки. Общий размер файла — не более 32 КиБ.
Каждое поле необязательно для Велеса; в этом репозитории для единообразия заполняются
все шесть. Повреждённое оформление не должно скрывать сам навык: неизвестные
и неподходящие поля пропускаются.

Краткое описание используется в Nerve с существующей возможностью перевода.
Названия задаются автором; отдельных полей для русской и английской локализации
в этом формате нет. Инструкции навыков должны учитывать язык пользователя.
`default_prompt` копируется отдельной кнопкой и не отправляется автоматически.
Велес не применяет `policy` и не подключает службы из `dependencies` этого файла;
другие клиенты могут понимать эти разделы. Сохраняйте их при редактировании чужого пакета.

## Требования к значкам

- PNG, JPEG, WebP или статический SVG; каждый файл не более **256 КиБ**.
- Фиксированного требования к размерам в пикселях нет.
- Для растровых значков рекомендуются квадратные 64×64 и 256×256 изображений.
  Один квадратный SVG можно использовать для обоих размеров.
- В этом репозитории применяются оригинальные геометрические SVG с областью
  `viewBox="0 0 64 64"`, одинаковой толщиной линий и индивидуальным рисунком каждого навыка.
- Пути считаются **от корня навыка**, а не от `agents/`. Используйте `/`.
  Запрещены абсолютные пути, `..`, внешние адреса и ссылки на файлы вне пакета.
- SVG хранится в UTF-8: без сценариев, обработчиков событий, объявления DTD,
  сущностей XML и внешних ресурсов. Простые фигуры и контуры предпочтительнее
  текста, встроенных изображений, анимации или сложных редакторских эффектов.
- Текущий сервер разрешает элементы `svg`, `g`, `path`, `rect`, `circle`,
  `ellipse`, `line`, `polyline`, `polygon`, `defs`, `linearGradient`,
  `radialGradient`, `stop`, `clipPath`, `mask`, `use`, `title`, `desc`.
  Ссылки внутри SVG допускаются только на локальный фрагмент `#id`.

Nerve сначала пробует малый значок, затем большой, затем `metadata.veles.emoji`
и общий значок. Прежний `icon.png` в корне поддерживается, если в оформлении нет
пригодного пути. Значки загружаются по идентификатору через защищённый маршрут
`/api/skills/icon`, а не напрямую по пути из YAML. Репозиторию не нужны собственные
адреса выдачи изображений. Рисунки интеграций здесь обозначают рабочие процессы,
а не воспроизводят официальные логотипы сервисов.

## Программы, секреты и настройки

Зависимости Велеса остаются в `metadata.veles` внутри `SKILL.md`:

```yaml
metadata:
  veles:
    emoji: "📚"
    requires:
      bins: [example-cli]
      env: [EXAMPLE_API_TOKEN]
    secrets:
      env: [OPTIONAL_API_TOKEN]
```

`requires.bins` перечисляет необходимые программы; `requires.env` — обязательные
секреты; `secrets.env` — необязательные. Декларация не устанавливает программу
и не создаёт подключение автоматически. Имена секретов: заглавные латинские
буквы, цифры и `_`, первый символ — буква или `_`, длина не более 128 символов.
В репозиторий входят только имена; значения находятся в зашифрованном хранилище
Велеса и передаются для конкретного вызова навыка. Прежний `metadata.openclaw`
поддерживается как запасной раздел при отсутствии `metadata.veles`.

Обычные настройки описываются в корневом `config.json` навыка:

```json
{
  "veles": {
    "endpoint": {"type": "string", "required": true},
    "limit": {"type": "number", "defaultValue": 5, "minValue": 1, "maxValue": 20}
  }
}
```

`type` — `string` или `number`; `required` — логическое значение.
`defaultValue` должен соответствовать типу и ограничениям. Числа поддерживают
`minValue` и `maxValue`, строки — `minLength`, `maxLength` и `pattern`
с полным совпадением. Неизвестные поля определений и смешение ограничений
разных типов отклоняются. Имя настройки непустое и без точек.
Файл — **схема**, а не пользовательские значения: они сохраняются в основной
конфигурации `skills.entries.<name>.config`. Вложенный `scripts/config.json`
не заменяет корневую схему маркетплейса.

## Подключение и обновление

В интерфейсе Велеса выбирают тип источника `github` или `gitlab`, видимое название,
адрес репозитория и необязательную ветку. Оба адаптера используют поля
`settings.repositoryUrl` и `settings.branch`; при пустой ветке выбирается ветка
репозитория по умолчанию. GitHub принимает публичный адрес HTTPS вида
`https://github.com/owner/repository`; интерактивный вход при загрузке отключён.
Учётные данные не должны находиться в адресе репозитория.

После изменения опубликованного репозитория нужна синхронизация маркетплейса.
Она обновляет каталог источника, но **не заменяет установленный навык**.
Пользователь отдельно устанавливает или обновляет выбранный навык. Установка
копирует всю его папку, включая `agents/`, `assets/`, программы и справки.
Изменение значка тоже меняет отпечаток содержимого и может предлагаться как обновление.
Перечитывание нового оформления из уже сохранённой папки источника не требует
повторной загрузки репозитория.

## Служебный каталог

Велес сам формирует `skills.json` **версии 1** в своём хранилище маркетплейсов,
рядом с загруженным `source/`. Автор исходного репозитория этот файл не поддерживает.
Новый раздел оформления не является новой версией формата маркетплейса.

| Уровень | Поля |
| --- | --- |
| Корень | `version: 1`, `syncedAt`, `source`, `skills`, `warnings`. |
| `source` | `revision`, `details`. |
| Запись навыка | `id`, `name`, `description`, `path`, `iconPath`, `secrets`, `settings`. |
| Необязательные поля навыка | `contentHash`, `requirements`, `interface`, `emoji`. |
| Предупреждение | `path`, `message`. |

`id` совпадает с `name`. `path` считается от загруженного источника; пути внутри
`interface` — от корня конкретного навыка. Старый `iconPath` относится к прежнему
`icon.png` и может быть `null`, даже когда новая SVG-иконка доступна.
`contentHash` учитывает пути и содержимое файлов. `requirements.bins` содержит
программы; запись секрета — `name`, `targetId`, `required`, без значения секрета.
Старые каталоги версии 1 без оформления остаются допустимыми.

Признаки установки, доступности программ, наличия секретов и возможности
обновления вычисляет Велес для выбранной рабочей области и личности. Они не
являются метаданными, которые следует записывать в исходный репозиторий.
Некорректные описания и схемы пропускаются с предупреждением; одинаковые
идентификаторы приводят к ошибке синхронизации. Не используйте дубликат
`SKILL.md` в документации как полный пример пакета.

## Совместимость и подготовка изменений

1. Сохраните совпадение имени папки и `name`; проверьте отсутствие дубликатов.
2. Уточните описание для модели в `SKILL.md`; оформление храните отдельно.
3. Укажите существующие значки и относительные пути, сохраните сведения об авторах.
4. Убедитесь, что программы, справки и картинки находятся внутри папки навыка.
5. Не добавляйте значения секретов, кэши, временные файлы или служебный `skills.json`.
6. После публикации синхронизируйте источник в Велесе и отдельно обновите установленную копию.

Навыки без оформления продолжают работать. При обращении к старому шлюзу,
не поддерживающему `agents/openai.yaml`, новые карточки и значки не появятся:
обновление репозитория само по себе не обновляет Велес или Nerve.
